# Slider

Порт `p-slider` из PrimeNG 21.1.10 (коммит `fe82b291d6`, см. `upstream.toml`).

| Наш компонент | Исходники PrimeNG |
|---|---|
| `prime-slider::Slider` | `packages/primeng/src/slider/slider.ts`, `slider/style/sliderstyle.ts` |
| CSS | `@primeuix/styles/slider` и пресет Aura (`cargo xtask gen-theme`) |
| Демонстрации | `apps/showcase/doc/slider/*-doc.ts` (`basic`, `range`, `step`, `vertical`, `filter`, `input`) |

Спека: `openspec/specs/slider`.

## Что совпадает с PrimeNG

- Структура: корень `div.p-slider`, внутри `span.p-slider-range` и ручки `span.p-slider-handle` (`role=slider`, `aria-valuemin/now/max`, `aria-orientation`); в диапазоне две ручки с `data-pc-section` `startHandler` и `endHandler`.
- Классы корня и их порядок: `p-slider p-component`, `p-disabled`, `p-invalid`, `p-slider-horizontal|vertical`, `p-slider-animate`; атрибуты корня `data-pc-name`, `data-pc-section`, `data-p` (ориентация), `data-p-sliding`.
- Клавиши: стрелки на `step` или 1, `PageUp`/`PageDown` на `step` или 10 (в диапазоне 1), `Home`/`End`; после каждого изменения фокус на активной ручке.
- Шаг: `handleStepChange` — сдвиг от прежнего значения на целое число шагов в сторону указателя (не округление до ближайшего шага); без `step` значение округляется вниз до целого, при дробном `step` — до его числа знаков.
- Клик по полосе двигает активную ручку (по умолчанию первую) и вызывает `on_slide_end`; клик, завершающий перетаскивание ручки, полосой не считается (`sliderHandleClick`).
- Касание: смещение пальца в процентах с округлением вниз плюс стартовое положение ручки (`onDrag`).
- Поддержка RTL и вертикальной ориентации (значение растёт снизу вверх).

## Отличия

| Отличие | Причина |
|---|---|
| Корень — `<div>`, а не хост `<p-slider>` | Хост в Angular — деталь фреймворка. |
| `value: RwSignal<f64>` и, при `range`, `values: RwSignal<[f64; 2]>` вместо `ngModel`; без сигнала внутреннее состояние | Двусторонняя привязка без форм-инфраструктуры. |
| Пара диапазона всегда упорядочена; при пересечении ручек активной становится другая, фокус идёт за значением | В PrimeNG внутренний массив остаётся неупорядоченным, а наружу уходит упорядоченная копия; в итоге значение и положение те же, но у нас нет расхождения между сигналом и внутренним состоянием. |
| Положение ручки всегда считается из значения | В PrimeNG тот же результат, но через отдельное поле `handleValue`. |
| Слушатели `mousemove`/`mouseup` вешаются на `window` на время перетаскивания | У PrimeNG на `document` через `Renderer2` и `NgZone`. Снимаются при отпускании и в `on_cleanup`. |
| Геометрия читается при каждом событии, клиентские координаты и `getBoundingClientRect` | Эквивалентно `pageX − (rect.left + scrollX)` PrimeNG, но не устаревает при прокрутке во время перетаскивания. |
| Флаг «нажата ручка» сбрасывается ещё и таймером после `mouseup` | В PrimeNG, если отпустить кнопку вне полосы, флаг остаётся и гасит следующий клик по полосе. |
| Нет `autofocus`, интеграции с Angular Forms | Вне объёма change. |
| В демонстрации `filter` градиентный блок вместо внешней картинки, `SelectButton` с `allow_empty=false` | Без зависимости от CDN; PrimeNG-вариант позволяет снять выбор и остаться без фильтра. |

Касание покрыто только чистыми функциями (`touch_percent`) и чтением кода; на сенсорном устройстве и синтетическими `TouchEvent` оно не проверялось (в `wasm-bindgen-test` они неудобны).
