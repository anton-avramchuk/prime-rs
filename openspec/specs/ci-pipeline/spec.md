# ci-pipeline Specification

## Purpose
Проверки на каждый PR и тяжёлые еженедельные проверки (e2e, скриншоты, браузерные бенчмарки), не блокирующие PR.

## Requirements

### Requirement: Проверки на каждый PR
CI на GitHub Actions SHALL при каждом PR выполнять: проверку форматирования, `clippy` с запретом предупреждений, юнит-тесты, `wasm-bindgen-test` в headless-браузере, `cargo-deny`, бенчмарки по спеке `benchmarking` и сборку для SSR и wasm. Браузерные e2e-тесты SHALL NOT выполняться на PR по умолчанию.

#### Scenario: Обычный PR
- **WHEN** открывается PR без особых меток
- **THEN** выполняются перечисленные проверки, а e2e-job не запускается

#### Scenario: Ошибка форматирования
- **WHEN** PR содержит неотформатированный код
- **THEN** job форматирования падает и блокирует слияние

### Requirement: Проверка только затронутых крейтов
CI SHALL определять изменённые крейты и зависящие от них крейты и запускать проверки компонентов только для них. При изменении общего ядра, зависимостей или конфигурации CI SHALL проверять весь workspace.

#### Scenario: Изменён один компонент
- **WHEN** PR меняет только `crates/prime-button`
- **THEN** тесты запускаются для `prime-button` и зависящих от него крейтов, остальные пропускаются

#### Scenario: Изменено ядро
- **WHEN** PR меняет `crates/prime-core`
- **THEN** проверяется весь workspace

### Requirement: Еженедельные и ручные проверки
E2E-тесты, сравнение скриншотов с PrimeNG и браузерные бенчмарки памяти SHALL запускаться по расписанию раз в неделю и вручную через `workflow_dispatch`, а также на PR с меткой `run-e2e`.

#### Scenario: Расписание
- **WHEN** наступает время еженедельного запуска
- **THEN** выполняются e2e, сравнение скриншотов и браузерные бенчмарки

#### Scenario: Метка на PR
- **WHEN** на PR добавлена метка `run-e2e`
- **THEN** запускается e2e-job

### Requirement: Эталон из PrimeNG без коммита бинарников
Сравнение скриншотов SHALL строить эталон в самом CI: клонировать PrimeNG на закреплённом коммите, собирать его showcase и снимать скриншоты. Эталонные изображения SHALL NOT коммититься в репозиторий. Артефакты сравнения SHALL храниться не более 7 дней.

#### Scenario: Запуск сравнения
- **WHEN** выполняется еженедельный job
- **THEN** эталон создаётся заново из закреплённого коммита, а результат публикуется как артефакт со сроком хранения не более 7 дней

### Requirement: Результаты сравнения не блокируют PR
Расхождения в скриншотах и в еженедельных проверках SHALL сообщаться отчётом и не блокировать слияние PR.

#### Scenario: Расхождение в скриншоте
- **WHEN** скриншот отличается от эталона
- **THEN** job публикует отчёт, но слияние не блокируется
