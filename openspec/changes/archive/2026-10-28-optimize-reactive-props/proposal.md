# Proposal

## Why

Одна из целей проекта — отсутствие лишнего потребления памяти и высокая производительность компонентов. Замеры Badge и Button (`docs/benchmarks.md`) показали: на экземпляр приходится 41 (Badge) и 67 (Button) аллокаций при SSR-рендере, тогда как «голый» `<span>` — 2. Эксперимент на `render-bench` разложил разницу:

| Вариант | Аллокаций на экземпляр |
|---|---:|
| `<span>` без реактивности | 2 |
| + одно `Memo` | 11 (+9) |
| + одно свойство `MaybeProp` | 5 (+3) |
| Badge сейчас | 41 |
| Button сейчас | 67 |

Каждое свойство `Signal<T>` или `MaybeProp<T>` создаёт запись в арене Leptos, даже когда передана константа или значение по умолчанию; плюс `Memo` для состояния и `class_memo` для классов. Менять компоненты после того, как на этот шаблон перейдут ещё десять-двадцать, будет в разы дороже, поэтому оптимизируем сейчас, пока образцов два.

## What Changes

- В `prime-core` появляется тип свойства `Prop<T>`: либо значение (`Static`), либо сигнал (`Reactive`). Статическое значение не создаёт реактивных примитивов; значения по умолчанию статические.
- `Badge` и `Button` принимают `Prop<T>` вместо `Signal<T>`/`MaybeProp<T>`: вызывающий код не меняется (`value="5"`, `loading=signal`, `severity=ButtonSeverity::Danger` продолжают работать).
- Из компонентов убираются `Memo` для состояния и `class_memo`: классы и атрибуты вычисляются в реактивных замыканиях атрибутов (при SSR каждое выполняется один раз, при работе в браузере — при изменении зависимостей).
- Добавляются проверяемые цели по аллокациям на экземпляр для `badge-1000` и `button-1000` (бюджет в `benches`), сравнение в CI уже есть (`bench-compare`).
- Поведение компонентов (классы, атрибуты, события, реактивность) не меняется; обновление `class` только при смене входных данных сохраняется.
- **Не входит:** оптимизация размера wasm (отдельно, после этого change), перенос остальных компонентов.

### Modified Capabilities
- `core-runtime`: новое требование о типе свойства «значение или сигнал» без реактивных затрат для статических значений.
- `badge`: новое требование к стоимости рендера (аллокации на экземпляр, отсутствие реактивных примитивов при статических свойствах).
- `button`: то же для Button.

## Impact

- Изменяются `crates/prime-core` (новый `Prop`), `crates/prime-badge`, `crates/prime-button`, `benches/render`, `benches/budgets.toml` (или отдельный бюджет аллокаций), `docs/benchmarks.md`, `docs/button.md`.
- Публичный API компонентов совместим на уровне исходного кода вызова (`#[prop(into)]` принимает те же выражения); типы свойств в сигнатурах меняются на `Prop<T>`.
- Риск: сборка `showcase` и демонстраций; закрывается их сборкой и e2e (`button.spec.ts`).
